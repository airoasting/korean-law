# korean-law 평가 세트

목적은 게이트가 가짜·낡은 인용을 잡는지, 그리고 **진짜 인용을 FAIL로 판정하지 않는지**(오탐 0)를 회귀 테스트로 확인하는 것이다.

## 구성

| 경로 | 내용 |
|---|---|
| `seeds.json` | 시드 24개. 기준일(`as_of`), 문서 본문, 인용별 정답(`truth`)과 기대 판정(`expect`), 문서 기대 판정 |
| `inputs/SNN.md` | 시드 본문 (스킬 절차로 돌릴 때의 입력) |
| `runs/YYYY-MM-DD/` | 시드별 `evidence.json`·`evidence.md`와 채점 결과 `score.md` |
| `blackdocs/YYYY-MM-DD/` | 도구 없이 AI가 쓴 실제 법무 문서와 실측 결과. 실전 가치 측정용 (정답 없음) |
| `tools/run-seeds.mjs` | 시드 전부를 엔진에 돌린다 |
| `tools/run-docs.mjs` | 문서 파일 여러 편을 엔진에 돌린다 |

가짜 인용 유형: T1 없는 조문, T2 제목 불일치, T3 미래 사건번호, T4 과거 연도 가짜 사건번호, T5 폐지 법령, T6 변경 판례, T7 옛 법령명, T8 삭제 조문, T9 부존재 법령. 정당한 인용 변형: T10 표기 변형, T11 약칭, T12 헌재 결정, T13 구법 인용, T15 시행 예정 개정이 있는 조문.

## 실행

인증키는 `mcp/.env`에 둔다. 저장소 루트에서:

```bash
cd mcp && npm run build && cd ..
```

```bash
node evals/tools/run-seeds.mjs evals/runs/<날짜>
```

```bash
python3 scripts/kl.py score evals/seeds.json evals/runs/<날짜> --out evals/runs/<날짜>/score.md
```

시드 24개가 30초 안팎에 끝난다. 기준일은 `seeds.json`의 `as_of`(2026-10-04)를 쓰므로, 법령이 바뀐 뒤에도 같은 결과가 나와야 한다. 결과가 바뀌면 엔진 회귀다.

엔진 단위 테스트(법제처 호출 없음)는 따로 있다.

```bash
cd mcp && npm test
```

## 합격선

| 지표 | 기준 |
|---|---|
| 진짜 인용을 FAIL로 판정 | 0건 |
| 가짜·낡은 인용 검출 (WARN 또는 FAIL) | 90% 이상 |
| FAIL이어야 하는 유형의 FAIL 판정 | 100% |
| 미검출 인용 | 0건 |

## 기록

| 날짜 | 오탐 | 정당 인용 적중 | 검출 | 엄격 FAIL | 미검출 | 문서 판정 | 비고 |
|---|---|---|---|---|---|---|---|
| 2026-10-04 | 0 / 63 | 100% | 23/23 | 17/17 | 0 | 23/24 | `runs/2026-10-04/score.md`. 시드 최대 5.6초 |

문서 판정 불일치 1건(S21)은 계약서 자기 조항(`제12조(면책)`)을 걸러내는 문맥 확인 전 결과다. 시드 러너는 엔진 1차 결과만 채점한다. 스킬 절차대로 문맥 확인(`EXCLUDED`)을 거치면 PASS가 된다.

실제 AI 작성 문서 실측은 `blackdocs/2026-10-04/FINDINGS.md`에 있다 (인용 81건 중 FAIL 3건, 오탐 0건).

## 갱신 기준

- 오탐이나 놓침이 실사용에서 나오면, 먼저 시드로 추가해 재현한다.
- 정답(`truth`)은 법제처 DB로 확인한 사실만 쓴다. 기대 판정(`expect`)을 바꾸면 `note`에 이유와 날짜를 남긴다.
- 엔진을 고치면 시드 회귀와 `npm test`를 둘 다 돌리고 위 기록 표에 한 줄을 더한다.
